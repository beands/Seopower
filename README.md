# RU Marketing Agent (SEO-first)

Переносимый Agent Skill для российского цифрового маркетинга и агентств. SEO остаётся сильной основой: Яндекс-first, Google как обязательный второй слой, GEO/AEO, Wordstat, Вебмастер, Метрика, локальный поиск и ecommerce. Полный аудит также оценивает платную рекламу, VK/Telegram/Дзен/Rutube, маркетплейсы и Avito, репутацию, CRM, конверсии и измерения.

Полный `audit` показывает карту всех направлений. Каждый канал получает подтверждённый статус и покрытие; отсутствие канала не считается проблемой и не ведёт к рекомендации запускать его без бизнес-основания. `seo-audit` сохраняет отдельный SEO-only режим.

## Принципы

- Findings и рекомендации опираются на evidence register и limitation log.
- Выгрузки платформ принимаются без требования API; публичные данные не подменяют закрытые расходы, лиды и продажи.
- Платформенную атрибуцию отделяем от CRM-квалификации, фактической выручки и маржи.
- Рекламные и privacy-требования отмечаются только как риски для проверки профильным юристом.
- Скрипты обрабатывают локальные файлы. Они не подключаются к кабинетам и не меняют внешние системы.

## Установка

Сохранено имя навыка `ru-seo-agent` для совместимости с уже установленными копиями.

Сначала клонируйте репозиторий. Windows PowerShell:

```powershell
.\install.ps1 -Target codex
```

Чтобы установить в другой каталог агента, укажите его имя в `-Target`:

```powershell
.\install.ps1 -Target codex
```

macOS/Linux:

```bash
./install.sh codex
```

Проверить структуру навыка можно так:

```bash
py -3 scripts/validate_skill.py
```

## Локальные данные и скоринг

Сохранить исходные строки выгрузки и нормализовать известные метрики:

```bash
py -3 scripts/import_channel_export.py export.csv --platform wildberries --captured-at 2026-10-03T12:00:00+10:00 --period 2026-09 --out normalized.json
```

Перед запуском удалите идентифицирующие данные клиентов. Helper работает офлайн, сохраняет исходные столбцы/значения и не проверяет файл на наличие персональных данных.

Те же параметры работают с JSON-выгрузкой в виде объекта, списка записей или `records`/`data` массива.

Скоринг рассчитывается только по направлениям с явными `applicability` и `coverage` в JSON. Без данных о покрытии балл отсутствует; общего балла marketing-аудита нет:

```bash
py -3 scripts/marketing_score.py findings.json
py -3 scripts/seo_score.py seo-findings.json
```

Чтобы получить модульный score, входной JSON должен явно задавать применимость `applicable` и полное покрытие `complete` в блоках `blocks`. Иначе балл по направлению не рассчитывается.

Модели, формат выгрузки и ограничения описаны в `references/marketing-channels.md` и `references/funnel-analytics.md`.

## PDF

Если пользователь запросил PDF, подготовьте его из готового Markdown-файла:

```bash
py -3 scripts/render_seo_report_pdf.py MARKETING-AUDIT.md --out output/pdf/MARKETING-AUDIT.pdf
```

На macOS/Linux используйте `python3`. Для кириллицы передайте Unicode TTF параметром `--font` или переменной `REPORT_FONT`.

## Источники и актуальность

Перед применением меняющихся правил платформ или требований проверяйте официальный источник и дату в `references/source-registry.md`. Проверка рекламы и персональных данных является issue spotting и требует юридической проверки.

## Новый клиент

```bash
py -3 scripts/init_client.py --out ./client-profile.md
```

Сценарий onboarding изучает доступные публичные материалы и выгрузки до вопросов. Секреты, пароли, cookies, идентифицирующие данные клиентов не сохраняются в профиле.

## Проверенные адаптеры и безопасность

- Нет встроенных токенов, скрытого scraping кабинетов, автоматических live writes, фейковых отзывов и гарантий результата.
